Case Study 01 — Parametric CAD Automation Platform

Engineering data → parametric CAD → assemblies → production drawings

Structured engineering inputs in; parametric geometry, SolidWorks models, assemblies and technical drawings out. Engineers review and adjust the parameters in the interface; the CAD work itself is automated.

Why I built it

I was doing this drafting work myself, and much of it was repetitive. A handful of VBA scripts removed the worst of it; once I had shown internally what the approach could do, I was moved onto the project full-time and have owned it end-to-end since.

Workflow impact

On supported cases, a complete staircase cage can be generated in around 5 minutes, with typical follow-up adjustments taking roughly 15–20 minutes. Comparable manual drafting could take around 8–12 hours for an experienced drafter, depending on the project.

For edge cases not yet fully automated, the system still produces a useful starting point instead of forcing engineers to rebuild everything from scratch.

These are observations from real workflow use within the supported scope, not a controlled benchmark.

03Selected technical challenges

01 / Process isolation
Parallel CAD instances
SolidWorks runs in isolated worker instances driven by a task orchestration layer, so generation does not interfere with the engineer's own open CAD session.
02 / Output validation
Trust measurements, not API success codes
A successful API call does not mean the geometry is right. Generated parts and drawings are checked against physical measurements, bounding boxes and the PDF output rather than taken on the API's word.
03 / COM interop
Working around a difficult COM interface
SolidWorks' COM interface is thinly documented at the edges. The Python integration is built around late binding, careful handling of COM object behaviour and edge cases discovered in practice.
